# 网页源 markdown 文档写法规范

---

## I. 列表

### 1.1 列表

列表开始前后必须是空行。

✅️ **正确写法**：

```markdown
列表开始：

- item1
- item2

列表结束
```

❌️ **错误写法**：

```markdown
列表开始：
- item1
- item2
列表结束
```

### 1.2 嵌套列表 

嵌套列表的缩进层级为 4 个空格。

✅️ **正确写法**：

```markdown
- item1
    - item1.1
    - item1.2
- item2
    - item2.1
```

不能是 2, 3 个空格，这些都无法正常被 Mkdocs 编译。

### 1.3 列表内嵌引用

这种写法一般不常用，但如果需要在列表项内嵌引用，推荐的写法是如下。

✅️ **正确写法**：

**(1) 引用缩进四个空格，前后空行（推荐这种方式）**

```markdown
1. item1

    > 这是一段列表项内部的引用。

2. item2
    
    > 内部引用

3. item3
```

或者：

**(2) 引用缩进三个空格，前后不用空行（不建议使用这种方式，mmf 工具不支持这种格式）**：

```markdown
1. item1
   > 这是一段列表项内部的引用。
2. item2
   > 内部引用
3. item3
```

### 1.4 列表内嵌代码块

这种写法一般不常用，但如果需要在列表项内嵌代码块，推荐的写法如下。

**代码块需要缩进四个空格，并且代码块前后需要空行。**

✅️ **正确写法**：

````markdown
- item1

    ```python
    print("inside list item")
    print("inside list item")
    print("inside list item")
    ```

- item2
````

❌️ **错误写法**：

````markdown
- item1
    ```python
    print("inside list item")
    print("inside list item")
    print("inside list item")
    ```
- item2
````

❌️ **错误写法**：

````markdown
- item1

   ```python
   print("inside list item")
   print("inside list item")
   print("inside list item")
   ```

- item2
````

## II. 公式

### 2.1 行间公式

**行间公式必须前后空行**（否则会被渲染为行内公式）。

✅️ **正确写法**：

```markdown
这是行间公式：

$$E = mc^2$$

这是行间公式：

$$
F = ma
$$

结束
```

❌️ **错误写法**：

```markdown
这是行间公式：
$$E = mc^2$$
这是行间公式：
$$
F = ma
$$
结束
```

### 2.2 行内公式

行内公式无特殊要求

## III. 代码块

代码块整体前后必须空行。

✅️ **正确写法**：

```markdown
这是代码块：

```python
print("hello, world!")
print("hello, world!")
```

结束
```

❌️ **错误写法**：

```markdown
这是代码块：
```python
print("hello, world!")
```
结束
```

## IV. 表格

表格前后必须空行。

✅️ **正确写法**：

```markdown
这是表格：

| Name | Age |
| --- | --- |
| Alice | 30 |

结束
```

❌️ **错误写法**：

```markdown
这是表格：
| Name | Age |
| --- | --- |
| Alice | 30 |
结束
```


## V. 正文

### 5.1 异常空格

典型的异常空格问题有：

1. 连续中文字符之间有空格，例如
    
    ❌️ **错误写法**：

    ```markdown
    CXL.mem 允许主机处理器将连接的 CXL 设备内 存 视 为 其 内 存 地 址 空 间 的 一 部 分。
    ```
2. 连续空格，例如：

    ❌️ **错误写法**：

    ```markdown
    Example 1: 
    CXL.mem 允许  主机处理器将连接的 CXL 设备内存视为其内存地址空间的一部分。
    
    Example 2:

    CXL.mem  允许主机处理器将连接的 CXL 设备内存视为其内存地址空间的一部分。
    ```

正确的空格用法：

1. 中文字符之间不允许有空格
2. 英文单词之间允许有空格
3. 中文字符和英文单词之间允许有空格，例如：
    
    ✅️ **正确写法**：

    ```markdown
    CXL.mem 允许主机处理器将连接的 CXL 设备内存视为其内存地址空间的一部分。
    ```

4. 中文字符和数字之间允许有空格，例如：

    ✅️ **正确写法**：

    ```markdown
    初始时设备 1 的 **HMC（host memory cache）** 中没有该主机数据的副本（处于无效态（I）），而设备 2 缓存中存在该数据的独占态副本（E）。
    ```

5. 不允许出现连续空格。
6. 特殊环境，例如：代码框（`code`, ```code```），公式框内的空格不受限制。

一个可行的判定方法就是：

检索正文（非特殊环境，即非代码框、公式框）中的每个空格，记该空格左侧和右侧的字符分别为 A 和 B：

1. 判定规则 1：如果 A 和 B 都是中文字符或者中文标点，则该空格为异常空格，需要消除；
2. 判定规则 2：如果 A 和 B 至少有一个英文字符或者数字，则该空格为正常空格，无需操作
3. 判定规则 3：如果 A 和 B 中至少有一个是非空格的特殊字符，例如：`@#$%^&*()_+-=~/\|[]{}` 以及英文标点，则该空格为正常空格，无需操作
4. 判定规则 4：如果 A 和 B 中至少有一个是空格，则该空格为异常空格，需要消除。将连续空格清除至单空格后，再执行上述判定规则 1~3。
